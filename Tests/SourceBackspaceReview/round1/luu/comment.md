**P2: Bound retries when an editing batch remains open.** `Sources/Editor/LinkingEditor.m:482–484` immediately re-arms the zero-delay common-mode callback at line 477 whenever `editedMask` still contains character edits. A native AppKit probe held an editing batch open across a 50 ms nested run-loop turn. It counted **3,396 schedules in default mode and 4,523 in tracking mode**, with no eligible removal until editing ended. A 1 ms heartbeat still fired 50 times, so the demonstrated regression is CPU churn rather than timer starvation. Use a bounded delayed retry or an editing-completion event, preserving pending suppression, cancellation, and eventual cleanup.

The remaining cost checks passed: 1,000 invalidations coalesce into one removal for 16 KiB and 1 MiB notes with 2,048 highlighted ranges; shared-storage cleanup is one callback per attached editor at 1/4/16 peers; the added dictionary copy occurs only while invalidation is pending and a background exists.

The harness extracts unchanged production methods into an adapter using real AppKit storage/layout and timers. It launches no GUI app. Timing numbers are descriptive, not pass/fail thresholds.
