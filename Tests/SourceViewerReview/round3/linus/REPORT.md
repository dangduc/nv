# Round 3: encoding identity and request ownership

Perspective: Linus Torvalds-inspired technical review, without impersonation.
Baseline: PR #4, `9720676ccd0e619dba99f6a47d257216c1e383eb`.

## Confirmed finding

**P2: Normalize encoding identifiers before deciding whether to reuse original source bytes.**

Location: `Sources/Model/NoteObject.m:175–176`.

A normal keyed archive decodes `fileEncoding` through a signed 32-bit integer at line 534.
The new `sourceOriginalEncoding` field uses an integer archive entry and retains its unsigned value.
For GB 18030, these become `0xffffffff80000632` and `0x80000632` on the Intel 64-bit target.
The strict comparison at line 175 rejects the original-byte path even when the source is unchanged.

The probe uses GB 18030 bytes `A3 A0`, which Foundation decodes as an ordinary ideographic space, U+3000.
Foundation encodes that character as `A1 A1`.
Before archive recovery, export retains `A3 A0`. After recovery, export returns `A1 A1` without a source edit.
GB 18030 is present in the application's Text Encoding menu.

The changed bytes also make `isSourceConflictCopyOfNote:data:encoding:` return `NO` for the recovered, unchanged conflict copy.
This defeats retry reuse for that encoding alias, despite the normalized comparison already present at line 202.
The probe verifies this predicate failure; it does not simulate another complete disk synchronization cycle.

Compare the canonical 32-bit encoding values at the original-byte boundary, or normalize the decoded identifier consistently.
Retain the current byte and source equality requirements.

## Rejected concerns and limits

Thirty Unicode fixtures cover UTF-8, both UTF-16 byte orders, and both UTF-32 byte orders.
They include empty source, literal leading U+FEFF characters, embedded NUL, a surrogate pair, and mixed line endings.
All preserve their characters and bytes across normal archives and edits on the baseline.
Mutable original-data inputs are copied.
Unrepresentable ASCII source returns an encoding error without lossy bytes; nullable error outputs work.

The request probe checks 100 duplicate offers, queued cancellation, cancellation followed by a new offer, and early success before presentation.
An old completion cannot upgrade the note or remove its replacement request.
Queued and completed requests release their note and library after their owning pool or copied completion ends.
All three note objects and library objects reach `dealloc`.

The request tests use lightweight alert and coordinator doubles, with real Foundation timers and copied Objective-C blocks.
They verify request ownership and token logic, not AppKit's actual sheet lifetime.
No desktop window, user library, network service, or production file is changed.
The Intel executable targets macOS 10.13 using the current SDK; execution was on the current host, not macOS 10.13.
